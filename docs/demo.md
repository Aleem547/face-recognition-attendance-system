# A concise demonstration

Use a separate synthetic administrator and linked student account. Keep actual student information and face images out of recordings and repository screenshots. The included images were rendered from synthetic local fixtures of the actual UI.

1. Show the administrator Overview and explain course analytics: closed sessions, role scope, Present + Late, Excused excluded.
2. Open a prepared class register. Explain the frozen roster and the difference between Unmarked and Absent.
3. Show a saved correction's receipt: old/new status, revision, reason, actor and server time. Show the corresponding CSV.
4. Switch to a linked student profile and show the student's own record and limited navigation.
5. Explain the camera positioning box and signed-in name. Describe optional live comparison as own-template research scores, bounded to a short run and not saved to attendance.
6. End with the documented limits: face/PAD reliability is unresolved, some manual acceptance scenarios are deferred, and deployment has not been included.

Suggested description:

> Face Recognition Attendance System is a role-based attendance prototype with frozen class rosters, persistent records, audited corrections, exports and scoped analytics. It also includes an optional consent-based face pipeline, a camera positioning guide, and bounded live own-template comparison. Experimental check-in can save a class mark, while biometric reliability and remaining manual acceptance work are still unresolved.

This is a presentation guide, not a request to repeat the paused manual tests. Do not present synthetic fixture screenshots as real evaluation results or claim that a name overlay identifies the face in view.
